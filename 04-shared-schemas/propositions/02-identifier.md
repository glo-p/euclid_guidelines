# Prop. IV.2 - Identifiers are ULID strings

| | |
|---|---|
| **Level** | MUST |
| **Status** | Accepted |
| **Since** | 2026-09-20 |
| **Owner** | Principal engineers |

## Statement

Every identifier (Def. I.18) exposed in a contract MUST conform to [`identifier.json`](../schemas/shared/v1/identifier.json): a 26-character ULID in Crockford base32, upper case, serialised as a JSON string. Identifiers MUST be generated by the system of record (Prop. VII.9) at creation time. Consumers MUST treat them as opaque: no parsing, no ordering assumptions beyond those the producer declares, no derivation of the creation time.

## Given

Def. I.18, Post. I.5, Post. II.5, CN 3, CN 5, Prop. II.5, Prop. II.11.

## Demonstration

One identifier shape across every contract is CN 5. Among the candidates, integers leak count and ordering and overflow JavaScript's safe integer range (Post. II.5); UUID v4 is unordered, which makes it a poor clustering key and a poor keyset-pagination tie-breaker (Prop. II.5); ULID is unique, URL-safe, fixed-width, string-typed (Prop. II.11) and lexicographically ordered by creation time, which gives a total order when combined with any sort key. The ordering is a producer-side property; by CN 3 a consumer may rely on it only where the contract says so, hence "opaque". ∎ Q.E.D.

## Corollaries

* **Cor. IV.2.1** - Database primary keys MAY be stored as 16-byte binary or as `uniqueidentifier`/`uuid` (a ULID is bit-compatible with a UUID); the contract still shows the 26-character string.
* **Cor. IV.2.2** - Externally assigned identifiers (a partner's order number, a VAT number) are *not* identifiers in this sense; they are string fields with their own schema and are never used as the resource id.

## Construction

.NET: `Ulid` from `Company.Contracts.Shared` (wrapping the `Ulid` NuGet package) with a `JsonConverter`, an EF Core value converter to `Guid`, and `Ulid.NewUlid()` using a monotonic generator per process. TypeScript: `type Identifier = string & { readonly __brand: "Identifier" }` plus a `isIdentifier()` guard.

## Conformance

Spectral `id-fields-are-shared-ref` (any property named `id` or `*Id` is a `$ref` to `identifier.json`). Catalogue CI validates the pattern.
