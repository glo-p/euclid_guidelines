# Prop. VIII.5 - API Gateway is the single ingress for APIs

| | |
|---|---|
| **Level** | MUST |
| **Status** | Draft |
| **Since** | 2026-09-20 |
| **Owner** | Principal engineers |
| **Supersedes** | - |

## Statement

Every synchronous API ([Book II](../../02-api-guidelines/README.md)) MUST be exposed only through Amazon API Gateway. Each environment MUST have one custom domain (`api.<env>.<company-domain>`) under which services are routed by path prefix. Load balancers, Fargate services and Lambda function URLs MUST NOT be reachable except from API Gateway.

## Demonstration

[Prop. II.12](../../02-api-guidelines/propositions/12-authentication-and-authorisation.md) and [Prop. V.1](../../05-security/propositions/01-every-api-behind-the-edge.md) place JWT validation and coarse authorisation at the edge; an edge exists only if there is one ([Def. VIII.11](../definitions.md#Def.%20VIII.11%20-%20Ingress)). A second reachable path would let a request bypass validation, and by [CN 3](../../01-foundations/common-notions.md#CN%203%20-%20Explicit%20Is%20Greater%20Than%20Implicit) anything not enforced at the declared edge is not enforced. Rate limiting ([Prop. II.13](../../02-api-guidelines/propositions/13-rate-limiting.md)) likewise needs one counter. [Post. I.8](../../01-foundations/postulates.md#Post.%20I.8%20-%20Stable%20Names) requires a stable name per environment; one custom domain per environment ([Def. VIII.4](../definitions.md#Def.%20VIII.4%20-%20Environment%20%28refines%20Def.%20I.21%29)) provides it without the name depending on which account or compute tier serves the path. [Prop. VIII.4](04-private-networking.md) removes public reachability from the compute behind it, and [Post. I.6](../../01-foundations/postulates.md#Post.%20I.6%20-%20Machine%20Verification) requires that removal to be checked. ∎ Q.E.D.

## Corollaries

* **Cor. VIII.5.1** - The path prefix of a service under the environment domain is the first segment of its resource names ([Prop. II.2](../../02-api-guidelines/propositions/02-resource-naming.md)) and is reserved in the catalogue.
* **Cor. VIII.5.2** - Internal service-to-service calls also go through API Gateway (private endpoint) so that [Prop. V.3](../../05-security/propositions/03-service-to-service-authentication.md) has one enforcement point.

## Construction

* API Gateway (REST or HTTP API; HTTP API default) per service, in the team account, deployed from the service's OpenAPI 3.1 document ([Prop. II.1](../../02-api-guidelines/propositions/01-contract-first.md)) with `x-amazon-apigateway` extensions generated by the pipeline.
* Central custom domain `api.<env>.<domain>` in the shared-services account with an ACM certificate, API mappings per service path prefix via cross-account base path mapping, or a per-team domain with Route 53 aliasing (open question).
* JWT authoriser ([Prop. V.1](../../05-security/propositions/01-every-api-behind-the-edge.md)) configured from the environment's OIDC issuer; usage plans and throttling per [Prop. II.13](../../02-api-guidelines/propositions/13-rate-limiting.md).
* Fargate integration via VPC link to an internal ALB; Lambda integration via the function's ARN; security group on the ALB admits only the VPC link ENIs.
* AWS WAF web ACL attached to every stage from a shared rule group.

## Conformance

AWS Config rules `api-gw-associated-with-waf`, `alb-internal-only` (custom), and a custom rule that no Lambda function has a function URL with `AuthType = NONE`; pipeline policy check that the deployed OpenAPI document equals the committed contract.

## Scholium

One front door means one place to look when something is wrong, one place to add a control, and one hostname to give a front-end team.
