# Prop. VIII.5 - API Gateway is the single ingress for APIs

| | |
|---|---|
| **Level** | MUST |
| **Status** | Draft |
| **Since** | 2026-09-20 |
| **Owner** | Principal engineers |
| **Supersedes** | - |

## Statement

Every synchronous API (Book II) MUST be exposed only through Amazon API Gateway. Each environment MUST have one custom domain (`api.<env>.<company-domain>`) under which services are routed by path prefix. Load balancers, Fargate services and Lambda function URLs MUST NOT be reachable except from API Gateway.

## Given

* Def. VIII.4, Def. VIII.11
* Post. I.6, Post. I.8, Post. I.9
* Prop. II.12, Prop. II.13, Prop. V.1, Prop. VIII.4
* CN 3

## Demonstration

Prop. II.12 and Prop. V.1 place JWT validation and coarse authorisation at the edge; an edge exists only if there is one (Def. VIII.11). A second reachable path would let a request bypass validation, and by CN 3 anything not enforced at the declared edge is not enforced. Rate limiting (Prop. II.13) likewise needs one counter. Post. I.8 requires a stable name per environment; one custom domain per environment (Def. VIII.4) provides it without the name depending on which account or compute tier serves the path. Prop. VIII.4 removes public reachability from the compute behind it, and Post. I.6 requires that removal to be checked. ∎ Q.E.D.

## Corollaries

* **Cor. VIII.5.1** - The path prefix of a service under the environment domain is the first segment of its resource names (Prop. II.2) and is reserved in the catalogue.
* **Cor. VIII.5.2** - Internal service-to-service calls also go through API Gateway (private endpoint) so that Prop. V.3 has one enforcement point.

## Construction

* API Gateway (REST or HTTP API; HTTP API default) per service, in the team account, deployed from the service's OpenAPI 3.1 document (Prop. II.1) with `x-amazon-apigateway` extensions generated by the pipeline.
* Central custom domain `api.<env>.<domain>` in the shared-services account with an ACM certificate, API mappings per service path prefix via cross-account base path mapping, or a per-team domain with Route 53 aliasing (open question).
* JWT authoriser (Prop. V.1) configured from the environment's OIDC issuer; usage plans and throttling per Prop. II.13.
* Fargate integration via VPC link to an internal ALB; Lambda integration via the function's ARN; security group on the ALB admits only the VPC link ENIs.
* AWS WAF web ACL attached to every stage from a shared rule group.

## Conformance

AWS Config rules `api-gw-associated-with-waf`, `alb-internal-only` (custom), and a custom rule that no Lambda function has a function URL with `AuthType = NONE`; pipeline policy check that the deployed OpenAPI document equals the committed contract.

## Scholium

One front door means one place to look when something is wrong, one place to add a control, and one hostname to give a front-end team.
